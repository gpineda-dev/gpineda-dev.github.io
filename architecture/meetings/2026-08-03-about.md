## 2. Cartographie de l'Écosystème Ouvrage Systems

Recensement des briques techniques et de leur articulation architecturale :

### 2.1 Extraction de Spécifications & Codex
* **`ouvrage-doc-etl-py` $\rightarrow$ `ouvrage-relieur-go`** : Pipeline ETL déterministe (PyMuPDF -> Physical IR -> Rules Engine -> Pandoc AST). Évolution vers une version Go microservices via gRPC et compilation WASI.
* **`ouvrage-hw-hid-codex`** : Transformation des specs brutes (`hut.json`) en schémas KCL/JSON immuables. Servis via `ouvrage-codex-mcp` pour éliminer l'hallucination des IAs.

### 2.2 Runtimes, Overlays & Stream Pipeline
* **`py-hid-declarative`** : Codec et compilateur Python type-safe pour USB HID (né du besoin de mapper un joystick Thrustmaster T.16000M via RPi4 vers un Xbox Adaptive Controller pour Battlefield 6).
* **`ouvrage-calque-go` (`ocalque`)** : Compilateur de templates déclaratifs sous forme d'overlays sémantiques (*calques*). Refus des variables mutables ("Helm Hell"). Intègre le *Shadow Pattern* (source exécutable en dev avec mocks, AOT-compilée pour la prod).
* **`ouvrage-stream-go` (`Ostream`)** : Protocole de bus de données pour codebases d'infrastructure (`application/x-yaml`, enveloppe 2k + N payloads 2k+1).
* **`ouvrage-kern-go`** : Cœur de grammaire pure (`pkg/lang`), zéro dépendance, conforme WASI Preview 2.

### 2.3 Projets Historiques / En Attente
* **`ProtocolSmith` / `flow-weaver-go`** : Testeur de charge réseau et moteur de workflows FSM déclaratifs en YAML.
* **`jobHangar` & `TheAtticLab`** : Orchestrateur de tâches distribuées pour archivage physique (numérisation et extraction sémantique autonome de 50 mini-DVD de famille sur S3 avec indexation Kuzu et interface MCP).
